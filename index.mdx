Network Policy Generator is a Kubernetes operator that eliminates the manual effort of writing NetworkPolicies. It observes real cluster traffic in **learning mode** to build data-driven policy recommendations, then applies them automatically in **enforcing mode** — across native Kubernetes, Cilium, and Calico CNI backends.

## Get Up and Running

<Steps>
  <Step title="Install the operator">
    Deploy Network Policy Generator into your cluster using Helm or a single `kubectl apply`.

    ```bash
    helm install npg oci://ghcr.io/somaz94/charts/network-policy-generator \
      --version 0.4.0 \
      --namespace npg-system --create-namespace
    ```
  </Step>
  <Step title="Create a NetworkPolicyGenerator resource">
    Apply a `NetworkPolicyGenerator` CR to start learning traffic patterns in a namespace.

    ```yaml
    apiVersion: security.policy.io/v1
    kind: NetworkPolicyGenerator
    metadata:
      name: my-app-policy
      namespace: default
    spec:
      mode: learning
      duration: 5m
      policy:
        type: deny
        allowedNamespaces:
          - kube-system
    ```
  </Step>
  <Step title="Transition to enforcing">
    After the learning duration elapses, the operator transitions automatically to enforcing mode and applies the generated NetworkPolicies.
  </Step>
  <Step title="Verify policies">
    ```bash
    kubectl get networkpolicygenerator
    kubectl get networkpolicy -A
    ```
  </Step>
</Steps>

<Note>
  Network Policy Generator requires Kubernetes v1.25+ for CEL validation rules in the CRD. For Cilium or Calico policies, the respective CNI must be installed in your cluster.
</Note>
